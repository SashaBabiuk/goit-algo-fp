# Фінальний проєкт з алгоритмів

У проєкті реалізовано всі сім завдань фінального проєкту.

## Структура

- `task1_linked_list.py` — однозв'язний список: реверсування посилань,
  сортування злиттям і злиття двох відсортованих списків.
- `task2_pythagoras_tree.py` — рекурсивна побудова та візуалізація дерева
  Піфагора. Рівень можна передати аргументом командного рядка.
- `task3_dijkstra.py` — алгоритм Дейкстри з `heapq` як бінарною мін-купою.
- `task4_heap_visualization.py` — перетворення масиву мін-купи на дерево та
  його візуалізація.
- `task5_tree_traversal.py` — ітеративні DFS і BFS зі стеком і чергою та
  генерація кольорів кроків обходу.
- `task6_food_optimization.py` — жадібний і 0/1 алгоритм динамічного
  програмування для вибору їжі.
- `task7_monte_carlo.py` — симуляція сум двох кубиків та порівняння з
  аналітичними ймовірностями.
- `test_final_project.py` — автоматичні тести.

## Запуск

Для алгоритмів і тестів достатньо Python 3.10+:

```bash
python3 task1_linked_list.py
python3 task3_dijkstra.py
python3 task5_tree_traversal.py
python3 task6_food_optimization.py
python3 task7_monte_carlo.py
python3 -m unittest -v
```

Для двох графічних завдань встановіть залежності:

```bash
python3 -m pip install -r requirements.txt
python3 task2_pythagoras_tree.py 8
python3 task4_heap_visualization.py
```

## Висновки

### Однозв'язний список

Реверсування змінює посилання між вузлами за `O(n)` часу та `O(1)` додаткової
пам'яті. Сортування злиттям працює за `O(n log n)` часу, а злиття двох
відсортованих списків — за `O(n + m)`.

### Дейкстра

Використання бінарної купи дає складність `O((V + E) log V)` для графа з
`V` вершинами та `E` ребрами. Алгоритм коректний для невід'ємних ваг.

### Обхід дерева

DFS використовує стек і йде вглиб, а BFS використовує чергу та відвідує
дерево рівнями. Обидва алгоритми мають складність `O(n)` часу.

### Вибір їжі

Жадібний алгоритм сортує страви за співвідношенням калорій до вартості та
працює за `O(k log k)`, але не гарантує оптимальний результат для задачі
0/1-рюкзака. Динамічне програмування працює за `O(kB)`, де `B` — бюджет, і
гарантує максимальну калорійність для цілочисельних вартостей.

### Метод Монте-Карло

За великої кількості кидків змодельовані ймовірності наближаються до
аналітичних значень `1/36, 2/36, ..., 6/36, ..., 1/36`. Випадкова похибка
зменшується приблизно як `O(1 / sqrt(n))`, тому збільшення кількості
симуляцій підвищує точність.
